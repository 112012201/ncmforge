## 一、本轮突破：沉浸声可以真正转码了

你提供的修补版 ffmpeg 里带着这个解码器：

```
 A....D libarcdav3a    AV3a decoder by ArcVideo (codec av3a)
```

**AVS3-P3 / Audio Vivid 解码问题解决了。** 已实测端到端跑通：

| 验证项 | 结果 |
|---|---|
| ffprobe 识别 | `codec_name=av3a`、`channels=12`、**`channel_layout=7.1.4`** |
| 解码为 WAV | 396,841,222 字节，24-bit / 12 声道 / 44.1 kHz / 249.96 s，exit=0 |
| 沉浸声 → FLAC 7.1 | 8 声道 `layout=7.1`，54.1 MB，含封面与歌词 |
| 沉浸声 → AAC-LC 5.1 | `profile=LC`、`channels=6`、`layout=5.1`、320 kbps，9.7 MB |
| 沉浸声 → MP3 立体声 | 2 声道，10.1 MB |
| 三种输出解码回验 | `ffmpeg -v error` **stderr 全为 0** |

注意：这个构建**只有 AV3a 解码器，没有 AV3a 编码器**。这正好够用——解码成 PCM 之后，用标准
编码器（FLAC / AAC / MP3）重新编码即可。

## 五、已知限制

1. **12 声道无法直接写入 FLAC**（规范上限 8 声道）。请选 7.1/5.1 降混，或用「原样无损提取」。
   AAC-LC 5.1 是兼容性与声道数的较好折中。
2. **音频没有真正的硬件编码器**（除 Media Foundation），见第二节。
3. 随附的 ffmpeg **只有 AV3a 解码器，没有编码器**——本工具也不需要它编码 AV3a。
4. **随附的 ffmpeg 是 GPLv3**。它以独立进程被调用，与 NcmForge 属聚合而非派生，因此 NcmForge
   自身不必采用 GPL；但再分发该二进制需保留许可证并提供源码获取方式。详见
   `tools/ffmpeg/NOTICE.txt`。**不需要时直接删除该目录即可。**
5. 本批 18 个真实样本中**没有出现 E-AC-3 / PCM 负载**，这两条路径用合成容器验证过。
6. `libfdk_aac` 在常见构建中不可用，AAC 使用 ffmpeg 原生编码器。
7. 单文件模式（`-SingleFile`）首次启动需可写的 `%TEMP%\.net`；默认的多文件布局没有这个问题。

## 六、快速命令速查

```bash
# 看本机 ffmpeg 能力（解码器 / 硬件编码器 / AVS3 支持）
ncmforge doctor

# 沉浸声 → AAC-LC 5.1（兼容性最好，通用播放器都能放）
ncmforge convert immersive.ncm --format auto --reencode --surround 71

# 沉浸声 → FLAC 7.1
ncmforge convert immersive.ncm --format flac --surround 71

# 沉浸声 → 保留全部 12 声道（不转码）
ncmforge convert immersive.ncm --format copy

# 用随附之外的 ffmpeg
ncmforge convert song.ncm --format auto --reencode --ffmpeg "D:\other-ffmpeg\bin"
```

发布：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1 -FfmpegDir "D:\ffmpeg-avs" -FfmpegInCli
```
